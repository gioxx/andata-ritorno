# A/R v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship A/R v2 at ar.gioxx.org: a public, local-first PWA with user-defined tabs, IndexedDB storage, sharper photos with a zoomable viewer, ZIP backups, and a zero-loss migration from the mockup.

**Architecture:** New Vite app in `app/` (plain ES modules). Pure logic (merge, v1 parsing, ZIP format, import planning) is separated from IndexedDB access (`db.js`) and from the DOM (`ui/*`), so the migration path is fully unit-tested. The current mockup is frozen in `legacy/` and gains a "moved" banner. Deployment is a static-only Wrangler config bound to the custom domain.

**Tech Stack:** Vite 7, Vitest 3 + jsdom + fake-indexeddb, `idb` (IndexedDB wrapper), `fflate` (ZIP), `vite-plugin-pwa` (service worker, precache), `@fontsource/plus-jakarta-sans` (self-hosted font), `lucide` (icons), Wrangler 4.

**Spec:** `docs/superpowers/specs/2026-10-23-ar-v2-design.md`

## Global Constraints

- UI copy in Italian; code and comments in English, comment density like `public/index.html` today (short "why" comments).
- Target Android Chrome; must not break on iOS Safari / desktop.
- Places are exactly `'school'` and `'home'`. At least one tab always exists.
- New photos: long side 1600 px, WebP q≈0.85, JPEG fallback when `toDataURL`/`toBlob` doesn't yield WebP. Migrated photos: bytes kept as-is, never re-encoded.
- No silent filtering of imported data, ever.
- Font Plus Jakarta Sans 500/600/700, self-hosted. Accent terracotta: light `#d96f4f`, dark `#e88563`.
- Light tokens: bg `#fbf7f1`, fg `#2b2620`, muted `#9a8f80`, school `#fde9d9`, home `#e3eedd`, tile `#fff`, chip `#efe7db`. Dark tokens: bg `#0d0f15`, surface `#151821`, tile/chip `#1f232e`, fg `#eceef5`, muted `#7c8296`, school stripe `#f0a531`, home stripe `#3bb273`.
- Radii: sections 22 px, tiles 16 px, chips/buttons pill (999 px).
- Theme preference stays in `localStorage['ar-theme']` (`'light'|'dark'`, absent = auto), applied before first paint.
- ar.gioxx.org serves static assets only; `/api/*` must not exist there. `worker/src` untouched.
- Nothing is deleted from the mockup or its storage automatically.

## Review Focus

1. **Storage quota exceeded** while adding photos or importing (`QuotaExceededError` from IndexedDB) → transaction aborts, nothing half-written, user sees "Memoria del telefono piena…" — test in Task 6.
2. **Same id twice inside one backup file** → treated as one item (newest per merge rule), counted once in the summary, never two records — test in Task 5.
3. **Non-image or undecodable file picked from gallery / pasted** (e.g. HEIC on a browser that can't decode it) → that file is skipped with a visible message naming how many were skipped; the others are added — test in Task 4.
4. **App open in two windows (installed PWA + browser tab) when a DB upgrade happens** → the old window closes its connection on `versionchange` and asks to reload instead of blocking the upgrade forever — test in Task 3.
5. **v2 ZIP item referencing a `tabId` that is neither in the file nor local, or a `photoId` with no file in `photos/`** → reported as a failed item (same failure screen as v1), not imported orphaned — test in Task 7.

### Task 5: Merge rule (`backup/merge.js`)

**Files:** Create `app/src/backup/merge.js`, `app/tests/merge.test.js`

**Interfaces:**
- Consumes: types from `types.js`.
- Produces: `buildPlan(local:{tabs,items}, incoming:Incoming) → ImportPlan`. Pure, no I/O.

Rules (spec "Merge rule"):
- Incoming duplicates by `id` within the file are first collapsed with the same rule (per field).
- Item not local → added (counts in `added`), its photo into `photosPut`.
- Item local → field-wise: `location` (and `movedAt`) from the side with greater `movedAt`; `label`, `tabId`, `category`, `photoId` (and `updatedAt`) from the side with greater `updatedAt`. Ties keep local. If the result differs from local → `itemsPut` and `updated++`. If `photoId` changed → incoming blob in `photosPut`, old local `photoId` in `photosDelete`.
- Tabs by `id`: new → put; existing → incoming `name`/`order` win only if `updatedAt` is greater.
- ISO strings compare lexicographically (all are `toISOString()` output).

- [ ] **Step 1: Write failing tests:**
  - `new item is added with its photo` → `added:1, updated:0`, photo in `photosPut`.
  - `newer move wins location, older edit keeps local label` — local `{movedAt:'…01', updatedAt:'…05', label:'A', location:'home'}`, incoming `{movedAt:'…03', updatedAt:'…02', label:'B', location:'school'}` → result `location:'school', label:'A'`, `updated:1`.
  - `same file twice is a no-op` — `buildPlan(afterFirstImport, sameIncoming)` → `added:0, updated:0, itemsPut:[]`.
  - `duplicate id inside file counts once` — incoming has same id twice (different `movedAt`) → `added:1`, `itemsPut.length:1`, newest location.
  - `replaced photo deletes old blob` → `photosDelete` contains old id.
  - `tab rename newer wins, older loses`.
- [ ] **Step 2:** FAIL. **Step 3:** Implement. **Step 4:** PASS.
- [ ] **Step 5: Commit** `"Add per-field last-writer-wins merge"`.

### Task 6: v1 parser and importer (all-or-nothing / partial)

**Files:** Create `app/src/backup/v1.js`, `app/src/backup/importer.js`, `app/tests/v1.test.js`, `app/tests/importer.test.js`, `app/tests/fixtures/v1-sample.json`

- Produces:
  - `parseV1(json, { childMap:Record<string,string>, now:string }) → Promise<Incoming>` in `v1.js`. For each item: validates `id`, `location ∈ {school,home}`, `child` string, `photo` via `dataUrlToBlob` + `decodeImage`. Invalid → `Failure` with Italian `reason` (`'Foto non leggibile'`, `'Dati incompleti'`, `'Posto sconosciuto'`), never dropped silently. Mapping: `tabId = childMap[child]`; missing child in map → creates a `Tab` `{ name: child==='nido'?'Nido':child==='materna'?'Materna':child, id: uuid }` and records it in returned `childMap`. Item fields: `createdAt = updatedAt = movedAt` (v1 has no edit clock), `photoId = uuid`.

  - `prepareImport(db, file, { childMap? }) → Promise<{ incoming:Incoming, plan:ImportPlan, needsMapping:string[] }>` — `needsMapping` lists v1 `child` values not in stored `meta.childMap` **when local tabs already exist** (UI asks, Task 12); when no tabs exist, auto-create.
  - `commitImport(db, prepared, { partial:boolean }) → Promise<Summary>` — if `incoming.failures.length && !partial` → throws `ImportBlocked` (carries failures), writes nothing. Else `applyPlan`; then persist `childMap`; if partial, append failures to `meta.todo`; then **verify**: re-`loadAll`, every planned item exists and `getPhoto(photoId)` returns a blob with `size>0`; mismatch → throws `Error('verify-failed')`.
  - `Summary = { added, updated, failed:number, perTab: Array<{ tabName, school:number, home:number }> }` and `formatSummary(summary) → string`, e.g. `"Importati 3 capi · Nido 2 (1 a scuola, 1 a casa) · Materna 1 (1 a scuola, 0 a casa)"`; when `updated>0` append `" · 2 aggiornati"`; when `failed>0` append `" · 1 da rifare"`.
  - Quota: any `QuotaExceededError` from `applyPlan` rethrown as `Error('quota')` (UI copy in Task 12).
