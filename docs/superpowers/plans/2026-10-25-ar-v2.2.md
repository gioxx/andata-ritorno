# A/R v2.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship A/R v2.2: photo rotation, one-per-item categories with tag filters, Italian + English, accessibility, iOS support, a readable Android navigation bar, and hardening — without touching existing data.

**Architecture:** Same Vite plain-JS app in `app/`. A small dictionary module drives all UI copy. IndexedDB goes to version 2 with a `categories` store; categories flow through store, merge, ZIP and importer like tabs do. Pure helpers (translation, filtering, platform detection, rotation bookkeeping) carry the logic and the tests; DOM code stays thin.

**Tech Stack:** Vite, Vitest (+ jsdom per file, fake-indexeddb), idb, fflate, lucide, vite-plugin-pwa, Wrangler (static assets + `_headers`).

**Spec:** `docs/superpowers/specs/2026-10-25-ar-v2.2-design.md` (builds on `docs/superpowers/specs/2026-10-23-ar-v2-design.md`)

## Global Constraints

- Local-first: no server-side data, no new network requests at runtime.
- No UI framework, no i18n framework; dependencies only if already present (idb, fflate, lucide).
- Code and comments in English; every user-visible string comes from the dictionary (Italian and English), user content (tab names, labels, renamed/custom categories) never translated.
- Language: `it` if `navigator.language` starts with `it`, else `en`; override stored in `localStorage['ar-lang']` (`'it'|'en'`, absent = auto), read before first render like the theme.
- One category per item (`Item.category` = category id or absent). Categories global across tabs. Defaults never created automatically.
- Default category ids and keys (fixed): `default-body` Body/Bodysuits, `default-tops` Maglie/Tops, `default-trousers` Pantaloni/Trousers, `default-dresses` Vestiti/Dresses, `default-jackets` Felpe e giacche/Sweatshirts & jackets, `default-pyjamas` Pigiami/Pyjamas, `default-underwear` Intimo/Underwear, `default-socks` Calze/Socks, `default-accessories` Accessori/Accessories — in this order.
- Rotation: one clockwise 90° button (lucide `rotate-cw`), commit only on save, re-encode WebP q 0.92 (JPEG fallback), net 0° writes nothing.
- Filter: OR across selected categories, "Tutti ✕"/"All ✕" clears, filter clears on tab switch, resets on reload.
- Visual style "Y" unchanged except contrast fixes; WCAG AA for text (4.5:1) and UI parts (3:1); touch targets ≥ 44 px; inputs font-size ≥ 16 px.
- Never lose data: DB upgrade v1→v2 preserves every tab, item, photo and meta entry.
- App version 2.2.0 in `app/package.json`.

## Review Focus

1. Upgrading a real v1 database (tabs, items, photos, meta) to v2 → every record and blob still there, byte-identical — test in Task 2.
2. Deleting a category that items use → items stay, become uncategorised, nothing else changes — test in Task 2.
3. A filter is active and the user taps a section counter or moves items → only the visible (filtered) items are selected/moved — test in Task 4.
4. A rotation is pending and the user closes the viewer / presses back / swipes → original photo untouched, no write — test in Task 5.
5. User renames a default category, then switches language → the renamed name stays as typed; untouched defaults follow the language — test in Task 3.
