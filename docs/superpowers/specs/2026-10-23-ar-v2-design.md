# A/R v2 — public local-first app — design

Date: 2026-10-23 · Status: draft, awaiting approval

## Intent

A/R ("Andata e Ritorno") tracks kids' clothes between home and school: each item has a photo and one state, **at school** or **at home**, and moves with a tap. Today it is a single-file localStorage mockup (`public/index.html`) used daily by one parent, happily. The goal is to turn it into a real, public app at **ar.gioxx.org**: anyone opens the URL, installs the PWA, uses it. No account, no setup.

This is project **1 of 3**:

1. **A/R v2 (this document)** — new look, user-defined tabs, IndexedDB storage, better photos, migration from the mockup. Local-only.
2. *Later:* family sharing (premium) — sync between phones via a share code / QR / temporary link, using the Worker + D1 + R2 already in `worker/`.
3. *Later:* payments to unlock premium.

v2 must not block 2: the data model is designed so items can later sync to a server (stable UUIDs, timestamps).

## Goals

- Users define their own **tabs** (today hard-coded "Nido" / "Materna"): add, rename, delete, reorder. A tab is a child or a school; its name is free text. When a child changes school, the user renames the tab and nothing else changes.
- The two **places stay fixed**: school and home. No third place (no "grandparents").
- A fresh, real-app look in light and dark (see Visual design).
- Photos stored in **IndexedDB** as Blobs, removing the ~5 MB localStorage ceiling (today's practical limit ≈150–250 items).
- **Better photos** for new items, and a **full-screen viewer with pinch-zoom** to inspect details.
- **Migration** of the existing mockup data with zero loss.
- Keep every current feature: camera, gallery multi-select, paste from clipboard (button + paste event), multi-select move, delete, export/import backup, unsaved-changes banner, last-backup info, persistent-storage request, light/dark/auto theme, side drawer menu.

### New small features

- Tap a section's counter to select all items in that section.
- Edit an existing item: label, photo (replace), tab.

## Non-goals (for v2)

- Categories / filter slider (shirts, pants, underwear…). Planned later; the data model gets an optional `category` field now, unused by UI.
- Per-item movement history view. Later.
- Any server-side storage, accounts, sync, payments (projects 2 and 3).
- iOS-specific polish. Target remains Android Chrome; must not break on iOS Safari/desktop.

## Anti-goals

- **Losing even one photo during migration.** This is the failure that matters most; it outweighs everything else.
- Adding complexity to the core flow (open → tap items → move). Simplicity first.
- Storing other people's photos on our server in the free tier.

## Constraints

- Hosting: Cloudflare (free tier), static assets served by a Worker, custom domain `ar.gioxx.org`.
- Different origin from the mockup (`andata-ritorno-mockup.<account>.workers.dev`), so the new app **cannot read** the mockup's localStorage. Migration goes through export → import.
- Offline-capable installable PWA.
- UI language: Italian. Code and comments: English (as today).

## Data model

```
Tab   { id: uuid, name: string, order: number, createdAt: iso }
Item  { id: uuid, tabId: uuid, location: 'school'|'home', label: string,
        category?: string, photoId: uuid, createdAt: iso, movedAt: iso, updatedAt: iso }
Photo { id: uuid, blob: Blob (image/webp or image/jpeg), width, height }
```

- Stored in IndexedDB (stores: `tabs`, `items`, `photos`, `meta`). Photos separate from items so lists render without loading full blobs into memory; the grid uses object URLs (or a small thumbnail — builder's call).
- `meta` holds settings currently in localStorage-ish keys: last backup time, unsaved-changes count, schema version. Theme preference may stay in localStorage (it must be read before first paint).
- Deleting a tab with items asks for confirmation, stating how many items will be deleted, then deletes them and their photos.
- Deleting the last tab is not allowed (there is always at least one).

## Photos

- New photos: resize to long side **1600 px**, WebP quality ~0.85 (JPEG fallback when the browser can't encode WebP, as today's Safari workaround). Target roughly 150–400 KB each. Exact numbers are the builder's call within that spirit: noticeably sharper than today, still light.
- Migrated photos keep their original 600 px resolution (that's all that exists); no upscaling.
- Full-screen viewer: tap-and-hold or a dedicated affordance opens it (tap is already "select"); pinch-zoom and pan, swipe/back to close. Builder decides the exact gesture, keeping tap = select.

## Backup format

- **v2 export: a ZIP** containing `backup.json` (tabs, items, metadata, `version: 2`) and `photos/<photoId>.<ext>` as binary files. Rationale (my call): with 1600 px photos, a base64 JSON would be ~33% larger and must be built as one huge string in memory. Use a small, well-known zip library (e.g. fflate); store photos uncompressed in the zip (they're already compressed).
- Export keeps today's behaviour: share sheet on Android (e.g. to Drive), download fallback, file name `andata-ritorno-YYYY-MM-DD.zip`.
- **Import accepts both** v2 ZIP and the mockup's v1 JSON.
- Import merges by `id`. Re-importing the same file creates no duplicates. Deletions are not propagated (documented limitation).
- Merge rule (my call; project 2's sync inherits it): **per-field last-writer-wins**. `location` is taken from whichever side has the newer `movedAt`; `label`, `photoId`, `tabId`, `category` from whichever side has the newer `updatedAt`. A move updates `movedAt` only; an edit updates `updatedAt` only. Tabs merge by `id` with their own `updatedAt` (a newer incoming rename wins). A photo replaced by the merge is imported as a new blob; the orphaned old blob is deleted in the same transaction.

## Migration from the mockup (zero-loss)

v1 format (from `public/index.html`): `{ app: 'andata-ritorno', version: 1, exportedAt, items: [{ id, child: 'nido'|'materna', location, label, photo: dataURL, movedAt }] }`.

Import of v1:

1. Map v1 `child` values (`nido`, `materna`) to tabs (my call):
   - From the welcome screen, "Importa un backup" skips creating a first tab; a v1 import then creates tabs "Nido" and "Materna" directly.
   - If tabs already exist, the import dialog asks, for each `child` present in the file, "new tab" (default, pre-named) or one of the existing tabs.
   - The chosen mapping `child → tabId` is stored in `meta`, so re-importing reuses it without asking.
2. Decode each `photo` data URL into a Blob; verify it decodes as an image (e.g. `createImageBitmap`). Keep the bytes as they are — **do not re-compress** migrated photos.
3. **All-or-nothing by default, partial only by explicit choice** (decided by the owner):
   - Everything is written in one IndexedDB transaction. If any item or photo fails validation, nothing is written yet; the user sees which items failed (label, tab, place, reason) and is advised to fix them in the mockup (retake the photo), re-export and retry.
   - The same screen offers an explicit second option: "Importa gli altri N" after confirmation. Then the valid items are written in one transaction, and the failed ones are kept in a visible "da rifare" list (label, tab, place) stored in `meta`, until the user dismisses each entry.
   - No silent filtering ever (today's importer silently drops invalid items — that must not happen).
4. After commit, re-read from the DB and verify counts and that every item has its photo.
5. Show a summary: total imported, per tab, school vs home, e.g. "Importati 87 capi · Nido 52 (30 a scuola, 22 a casa) · Materna 35 (…)". The user compares with the mockup's counts.

### Mockup changes

- Freeze the current mockup source (e.g. move it to `legacy/` and point `wrangler.mockup.toml` at it) so v2 work in `public/` doesn't change it.
- Add one thing to the mockup: a top banner "A/R si è trasferita su ar.gioxx.org" with two buttons, **Esporta backup** (existing export) and **Apri la nuova app** (link). Everything else in the mockup keeps working.
- The mockup stays online until the owner decides to shut it down. Nothing is ever deleted automatically.

## Visual design (decided with the owner)

Chosen direction: **"Y"** — light from the "Morbido" direction, dark from the "Pulito" direction, unified by shape and accent. Mockup: `.superpowers/brainstorm/*/content/visual-style-v2.html` (not committed; tokens below are the source of truth).

- Font: **Plus Jakarta Sans** (500/600/700), self-hosted for offline use.
- Shape: rounded; sections radius ~22 px, item tiles ~16 px, chips and buttons pill-shaped.
- Accent: **terracotta** in both themes (light `#d96f4f`, dark `#e88563`): primary buttons, active tab, selection outline/check.
- Light: background cream `#fbf7f1`, text `#2b2620`, muted `#9a8f80`, school section `#fde9d9` (peach), home section `#e3eedd` (sage), tiles white, chips `#efe7db`.
- Dark: background `#0d0f15`, surfaces `#151821`, tiles/chips `#1f232e`, text `#eceef5`, muted `#7c8296`. Sections neutral, distinguished by a thin left stripe: school amber `#f0a531`, home green `#3bb273`.
- Theme: light / dark / auto (follows system), as today.
- Header: app title + menu button; tabs as horizontally scrollable chips with a "+" chip to add.
- Sections "A scuola" / "A casa" with item count badge (tap = select all in section); 3-column photo grid; selected item shows outline + check badge.
- Bottom bar is contextual (as today): no selection → "Aggiungi capi" (+ "Incolla" when relevant); selection → "Annulla (n)", "→ Scuola"/"→ Casa", delete.
- Builder's calls: real icon set instead of emoji (🏫/🏠 in section titles may stay), new app icon and splash in this style, subtle move animations, exact spacing.

## First run

- Empty state / welcome: ask the name of the first tab (e.g. "Nido di Sofia"), and offer "Importa un backup".
- A discreet note that data stays on this phone and backups are recommended. Request persistent storage (as today).

## Hosting

- ar.gioxx.org is served by a **new static-only Wrangler config** (like `wrangler.mockup.toml`) pointing at the Vite build output (my call). The API Worker (`worker/wrangler.toml`, `worker/src`) is **not** deployed to ar.gioxx.org in v2: `/api/*` must not be reachable publicly (it has no auth of its own). Project 2 revisits this.

## Tech

- Stack: plain JavaScript (no heavy framework) with a small build step (e.g. Vite) to bundle, hash assets and self-host fonts. Builder's call on structure.
- Service worker with real offline caching of the app shell (today's SW is a no-op).
- Deployed as static assets via Wrangler to `ar.gioxx.org` as a Worker Custom Domain (the `gioxx.org` zone is on the same Cloudflare account). The existing API Worker code in `worker/src` stays untouched (project 2).

## Left to the builder

File/module structure, build tool details, IndexedDB wrapper (raw or tiny lib such as idb), thumbnail strategy, exact photo size/quality within the stated range, viewer gesture, animations, icon set, tests approach. Verification of the migration path with a real v1 export is mandatory before release.
